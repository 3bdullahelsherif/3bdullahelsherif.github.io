Engineering notes

Short write-ups from real problems I solved

Running Global Math on $0 a montharchitecture

A sold, live product with paying stakeholders still costs the client nothing to host. The frontend sits on Vercel's free tier, the NestJS API on Render's free tier, the database on Neon's free Postgres, and videos on Cloudflare R2, which has no egress fees.

The real work is in the constraints: free tiers sleep, so health checks and an uptime monitor keep the API warm, and heavy jobs like video transcoding run as queued background workers instead of blocking requests.

Beating YouTube's transcript wallbrowser extensions

While building Mulakhas, YouTube's transcript URLs started returning empty responses gated by bot detection tokens. The fix was a three-step fallback chain: read the player data already inside the page, then re-fetch the watch page, then ask YouTube's mobile client endpoint, which still serves classic transcript XML.

Validated against a real 10-hour Arabic course: 11,359 transcript segments parsed, grouped and formatted for the AI prompt.

One shared core, five extensionsbrowser extensions

All five Arabic web tools share one vendor layer: AI calls, Arabic text processing and offline summarization. Each extension is then a thin Manifest V3 shell with only its own UI and logic, which is how all five stayed small and testable.

32 automated tests cover the shared core and each extension's logic, and every AI flow was verified live in a real browser before calling it done.
